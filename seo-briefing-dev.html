Rigenerato dagli appunti il 12/10/2026. Destinatario: Giovanni (sviluppatore Novarium — i permessi per modifiche al repo passano da lui).

Contesto: nuovo sito Next.js (158.550 URL in sitemap, 31.666 prodotti × 5 lingue). Problema madre: le pagine prodotto non vengono indicizzate (sonde ~1% con impressioni in 6 mesi) e il traffico Parts poggia su URL legacy a rischio.

FASE 0 — Sblocco crawl e canonicalizzazione (urgente)

Ticket 0.4 — Paginazione server-side + internal linking

  • La paginazione dei listing è solo JS (~8 link per pagina brand) → i prodotti sono orfani per Google.
  • Implementare paginazione crawlable server-side (link <a href> reali, rel next/prev o equivalente) + linking interno contestuale (brand → macchina → prodotto).

Ticket 0.5 — 301/404 delle combo URL non canoniche

  • Il sito espone fino a ~25 varianti per prodotto (5 prefissi lingua × 5 slug lingua), incluse combo ibride (es. /en/products/sondes-ecographiques/...).
  • Ogni prodotto deve avere 1 sola URL canonica per lingua; tutte le altre combo → 301 alla canonica (o 404 se senza equivalente).

Ticket 0.x — Consolidamento host

  • non-www → 301 verso www (oggi risponde 200: duplicato completo; 27% impressioni su non-www, pos. media 11,6 vs 6,6).

Ticket 0.y — Redirect legacy /vendita/marca/

  • Oggi: 301 verso ricerca interna noindex → il 42% del traffico Parts evaporerà.
  • Redirect verso hub indicizzabili equivalenti (pagine brand/macchina del nuovo sito).
  • Fix tampone se il go-live del nuovo sito slitta >4 settimane: 301 da /vendita/marca/ verso hub indicizzabili del sito attuale.
  • Redirect L8 attivo lo stesso giorno del cutover, non dopo.
  • Mappe redirect versionate in git + script di rigenerazione.

Ticket 0.z — Legacy da eliminare

  • /vendita/prodotto/?pid=N → 404 (mappare verso prodotto nuovo o 410).
  • Redirect ?lang= legacy → correggere lingua di destinazione.

  1. Hreflang via sitemap (5 lingue, x-default incluso).
  2. Product schema completo su pagine prodotto: fix "1 invalid item" (campo offers/review mancante) → rich results.
  3. Template title/H1 arricchiti: marca + modello + tipo (sonda/ricambio) + macchina compatibile.
  4. Pagine categoria-macchina statiche (es. "Sonde GE Voluson").
